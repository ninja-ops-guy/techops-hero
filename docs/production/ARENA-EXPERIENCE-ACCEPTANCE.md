## Implemented in this lane

Client controls now retain independent physical-key and pointer ownership, normalize shifted letters, reject pre-session/nonplaying input, preserve short taps until the next send, and clear held/pending controls on blur, visibility change, room transitions and request errors. Focused control buttons support Space/Enter and assistive activation; focused lobby/ready controls keep native activation. Leaving or confirmed 401 clears obsolete health/canvas content; late responses cannot restore the old match.

Requests have a five-second abort deadline. Transient failures, 409 and 429 retain the current seat, release controls and retry through `poll` with 250 ms to two-second bounded backoff. Initial, waiting and terminal states use `poll`; only countdown/fight use `input`. This depends on the integration owner's existing `poll` response fields and optional `state.outcome={reason,winner}` terminal result. This is neither reconnect nor guaranteed input delivery: an unacknowledged short press is not replayed without an input-ID protocol. A dropped ready response is safe to retry: the next poll shows server readiness, and repeated readiness must remain an idempotent vote server-side.
